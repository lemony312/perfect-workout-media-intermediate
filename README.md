# perfect-workout-media-intermediate

The **intermediate** salsa clips for [perfect-workout](https://github.com/lemony312/perfect-workout),
served as a GitHub Pages site and loaded cross-origin by the app.

## Why this is a separate repo

GitHub Pages publishes at most **1 GB per site**. The salsa clips were split out of the
main repo once already, into `perfect-workout-media`, to get the app's own site back
under that limit. Adding the two intermediate courses then took *that* site to 1035 MB
— over the limit, which means it does not deploy at all and every clip in all four
courses 404s, not just the new ones.

The alternative was re-encoding at a higher CRF. That was measured: CRF 26 would have
saved 27%. It was rejected because the loss lands in motion, and motion is exactly what
you are reading in a dance clip — which foot moves on which beat. A second repo costs
some wiring and no picture quality, so the clips stay at CRF 23.

The split is by path prefix. Everything under `/clips/salsa/intermediate/` lives here;
the beginners clips stay in `perfect-workout-media`. `frontend/src/lib/media.ts` in the
main repo is the single place that decides which origin a path resolves against.

Both sites now sit near half full:

| Site | Contents | Size |
|---|---|---|
| `perfect-workout-media` | beginners steps + couples clips | ~524 MB |
| `perfect-workout-media-intermediate` | intermediate steps + couples clips | ~511 MB |

## Do not edit these files by hand

Every clip is generated by `scripts/clip_salsa_intermediate.py` in the main repo, from
windows recorded in `SALSA_INTERMEDIATE_SPEC_PARTA.md` through `PARTE.md`. The
authoritative list of paths and windows is `CLIP_MANIFEST_INTERMEDIATE.md` there. To
change a clip, change the spec window and re-run the script — a file edited here would
be silently overwritten and its provenance lost.

`.nojekyll` is required: without it Pages runs the files through Jekyll, which drops
paths it does not recognise.
